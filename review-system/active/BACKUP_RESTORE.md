# 第一服务研发小组审核系统备份恢复说明

## 这份备份里包含什么

- `frontend/`
  - 前端源码
  - `node_modules`
  - `package.json`
  - `package-lock.json`
- `backend/`
  - 后端源码
  - `node_modules`
  - `package.json`
  - `package-lock.json`
  - `data/store.json`
  - `data/files/`
- `deploy.sh`
- `nginx.conf`
- `README.md`

这意味着恢复后不需要重新录入账号、方案、附件、日志、机器人配置和规则数据。

## 当前恢复口径

- 登录地址：`http://127.0.0.1:5174`
- 后端地址：`http://127.0.0.1:3001`
- 管理员账号以 `backend/data/store.json` 中的数据为准。生产环境恢复后请立即主动修改默认管理员密码，或在人员管理中重新设置管理员账号。管理员不会被强制下次登录改密，使用者账号可按安全策略开启强制改密。

## 推荐恢复方式

### 方式一：原样恢复到本机

1. 解压备份包
2. 进入项目目录
3. 分别启动前后端

后端：

```bash
cd backend
PORT=3001 npm start
```

前端：

```bash
cd frontend
npm run dev -- --host 0.0.0.0 --port 5174
```

### 方式二：只恢复源码和数据，再重新安装依赖

如果你不想保留 `node_modules`，可以删除前后端的 `node_modules` 后重新安装：

```bash
cd backend
npm install
```

```bash
cd frontend
npm install
```

然后按“方式一”启动。

## 最关键的数据位置

- 账号、方案、审核日志、规则、知识库、机器人配置：
  - `backend/data/store.json`
- 已上传附件：
  - `backend/data/files/`

只要这两个位置没丢，核心业务数据就能恢复。

## 在线备份

管理员可以进入“系统设置”，在“数据存储”卡片点击“下载备份”。备份文件为 JSON，包含：

- `store.json` 中的账号、方案、日志、规则、知识库、机器人、权限和系统配置
- `backend/data/files/` 下的附件内容（Base64 编码）
- 新版备份会为每个附件写入 `sha256` 校验和，并生成备份整体校验码

每次在线备份会写入一条系统配置审计日志。备份下载会优先使用后端返回的文件名，便于和日志 CSV、Hermes Profile、知识库导出文件统一归档。

## 在线校验与恢复

管理员可以进入“系统设置”的“备份文件校验”区域，上传备份 JSON。系统会先校验文件结构并展示摘要，不会立即覆盖当前数据。

新版备份会在校验阶段核对附件大小、附件 `sha256` 和备份整体校验码。如果附件内容、业务数据或附件清单被截断或篡改，系统会拒绝继续恢复。旧版备份没有校验和时仍可恢复，但页面会显示“旧版未记录”。

确认恢复时需要：

1. 上传并通过备份校验
2. 在确认输入框输入 `确认恢复`
3. 点击“确认恢复备份”
4. 浏览器提示二次确认后继续

恢复会覆盖当前账号、方案、日志、规则、知识库、机器人配置、权限、系统配置和附件。恢复前，后端会自动保存一份当前数据快照到：

```text
backend/data/backups/pre-restore-*.json
```

恢复完成后当前登录态会失效，需要重新登录。

## 本地备份快照

“系统设置”的“本地备份快照”区域会展示最近的服务端快照，管理员可以手动创建服务器本地备份、刷新列表、预览快照、下载快照、直接从快照恢复，也可以删除不再需要的快照。该能力用于在执行高风险操作前留存当前数据，或在误恢复、恢复文件不符合预期时拿回恢复前的数据。

快照区域会显示总数、总大小、手动备份数量、恢复前快照数量和最近更新时间，用于判断是否需要清理旧快照。

手动快照文件名格式为：

```text
backend/data/backups/manual-backup-*.json
```

恢复前自动快照文件名格式为：

```text
backend/data/backups/pre-restore-*.json
```

从本地快照恢复同样需要输入 `确认恢复`。恢复前建议先点击“预览”，确认账号、方案、日志、附件校验和整体校验状态。恢复前，系统会再自动保存一份当前数据快照，避免二次误操作。

删除快照只会删除 `backend/data/backups/` 下对应的 JSON 文件，不会影响当前运行数据。创建、预览、下载、恢复、删除和批量清理动作都会写入系统配置审计日志。账号批量改密、停用、解锁会写入账号安全审计日志，并记录请求数、实际更新数、跳过数和跳过原因。

如果快照较多，可以输入保留天数并点击“清理旧快照”。系统会删除早于保留天数的恢复前快照，并记录清理数量到审计日志。

## 换号或重装后建议先检查

1. Node.js 是否可用
2. `backend/data/store.json` 是否存在
3. `backend/data/files/` 是否存在附件
4. 前端是否显示版本 `v0.0.16`
5. 是否能用管理员账号登录，并已主动修改默认管理员密码
6. 人员管理中管理员/使用者权限边界是否正确，必要时导出账号安全清单
7. Hermes Profile 接入检查是否 8 个一级专业均已匹配
8. 日志中心是否可导出账号安全、AI 调用、Hermes 配置和上线确认 CSV
9. 如执行过在线恢复，检查 `backend/data/backups/` 是否存在恢复前快照

## 说明

浏览器本地 `localStorage` 登录态不会一起迁移，但这不影响使用。恢复后重新登录一次即可。
